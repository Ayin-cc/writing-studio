# 研究与事实核查

给任何体裁供料、补引用、核查事实。由创作线调用，也可单独使用。

## 1. 研究

1. **确定问题清单**：从大纲里把需要证据的主张逐条列出，每条写清要找的是数据、案例、引述还是背景。
2. **找来源**：用 WebSearch / WebFetch 或用户给的材料。来源可信度从高到低：原始数据与官方文件 → 同行评审论文 → 权威媒体原始报道 → 行业报告 → 二手转述。自媒体和 AI 生成内容不能做唯一来源。
3. **记进 `research.md`**：

```markdown
## <问题>
- 结论：……
- 证据：原文摘录（短）或数据
- 来源：作者/机构，标题，日期，URL
- 可信度：高 / 中 / 低，理由
- 用在：大纲第 X 节
```

4. **平衡视角**：有争议的话题至少找一个反方来源，正文里如实反映分歧。

学术文献检索和梳理可参考 `references/library/academic/agents/paper-crawler.md`、`research-analyst.md`。

## 2. 引用格式

按用户要求选一种，全文统一：

- 行内：`……提升了 40%（McKinsey, 2024）。`
- 编号：`……提升了 40% [1]。` 文末列 `[1] 作者. (年份). 标题. 出处. URL`
- 脚注：`……提升了 40%^1`
- 学术：按目标期刊的样式（APA、GB/T 7714 等），检查规则见 `library/academic/agents/bibliography-auditor.md`。

视频稿不放引用编号，在稿件末尾附"资料来源"清单，需要时让关键数据上屏标注出处。

## 3. 事实核查

交付前对稿件逐条扫描以下内容：

| 类型 | 核查方法 |
|---|---|
| 数字、比例、金额 | 回到原始来源核对数值、单位、统计口径、年份 |
| 人名、机构名、职务 | 拼写和头衔以官方来源为准 |
| 日期、时间顺序 | 核对事件先后，防止因果倒置 |
| 引语 | 找到原话出处；查不到就改成转述并注明来源，或删掉 |
| "研究表明""专家认为" | 必须落到具体研究或具体专家，否则删掉或改写 |
| 因果断言 | 来源说的是相关还是因果，不能拔高 |
| 时效性 | 价格、政策、版本号、排名是否过时 |

核查结论标在稿件里或单独列表：

- ✅ 已核实（附来源）
- ⚠️ 部分属实或需限定（写明怎么改）
- ❌ 有误（给出正确信息和来源）
- `[待核]` 找不到可靠来源。不得猜测补全，交付时明确告诉用户

## 4. 底线

- 不编造数据、引语、文献、URL。引用前确认 URL 能打开、内容和引述一致。
- 用户自己提供的事实默认采信，但发现明显错误时要指出。
- 虚构作品（剧本、小说）里的虚构内容不需要核查；但涉及真实历史、真实人物、专业知识（医疗、法律、科学）的细节仍需核对。
