# 专业文档：结构、论证、格式

覆盖 PRD、技术方案、设计/决策文档、报告、提案、论文、文章与专栏、科普、公众号/小红书长文、营销与商业文案。

## 1. 收集上下文

先问清五件事（可一次问完，允许简写回答）：

1. 文档类型（技术方案 / 决策文档 / 报告 / 文章 / 文案……）
2. 主要读者是谁，他们已经知道什么
3. 读者读完要做什么：批准、理解、执行、购买、转发
4. 有没有模板、范文、格式要求、字数限制
5. 其他约束：截止时间、敏感信息、必须提到或不能提到的内容

然后请用户把材料一股脑丢过来：背景、讨论记录、相关文档、为什么不选别的方案、利益相关方的顾虑。不用整理。

材料读完后，再提 5–10 个编号问题补齐缺口。能问到边界情况和取舍、而不用再问基础事实时，说明上下文够了。

## 2. 搭结构

按类型给 3–6 节的骨架，用户确认后建文件并为每节写占位。常用骨架：

| 类型 | 骨架 |
|---|---|
| 决策文档 | 结论与建议 → 背景 → 方案对比 → 风险与代价 → 需要谁做什么决定 |
| 技术方案 / 设计文档 | 目标与非目标 → 现状 → 方案设计 → 备选方案与取舍 → 迁移/上线计划 → 风险 → 待定问题 |
| PRD | 问题与用户 → 目标与成功指标 → 范围（做/不做） → 需求与用户故事 → 交互/流程 → 依赖与里程碑 |
| 报告 | 摘要（结论先行） → 发现 → 依据与数据 → 建议 → 附录 |
| 文章 / 专栏 / 科普 | 钩子 → 为什么值得读 → 2–4 个主体段 → 反方观点与回应 → 收尾与行动 |
| 公众号 / 小红书长文 | 标题与首屏钩子 → 场景或痛点 → 干货分点 → 个人观点 → 互动引导 |
| 商业文案 / 落地页 | 一句话价值主张 → 痛点 → 方案与证据 → 异议处理 → 行动号召 |
| 论文 | 摘要 → 引言（目标-问题-方案） → 相关工作 → 方法 → 实验 → 讨论与局限 → 结论 |

从未知最多的那节开始写（决策文档通常是"建议"，技术方案通常是"方案设计"），摘要最后写。

## 3. 逐节写作

每一节走同样的小循环：

1. 问 3–5 个这节具体要写什么的问题。
2. 列 5–15 个可写要点，让用户按编号取舍（"留 1、4、7；删 3，和 1 重复；合并 11 和 12"）。
3. 问一句是否还漏了什么。
4. 起草，替换占位。
5. 按反馈做局部修改。连续三轮没有实质改动时，问"有没有能删而不损失信息的内容"。

用户直接改了文档时，读出他们改了什么，把偏好用到后面的章节。

## 4. 论证要求

- **结论先行**：每节第一句就是这节的主张，后面给依据。
- **一段一个意思**，段尾回扣主张，不留悬空段落。
- **证据分级**：数据 > 案例 > 权威引述 > 推理。没有证据的主张标 `[待核]`，交给研究模块。
- **主动处理反方**：读者最可能的质疑写在正文里回答，不要等评审时被问。
- **把不确定说准**：区分"已验证 / 预计 / 假设"，不要处处加"可能"。
- **局限放对位置**：技术文档和论文的局限放在讨论或风险节，不在开头自我削弱。

## 5. 读者测试（交付前）

在 Claude Code 里用子代理做：

1. 预测 5–10 个读者会问的问题。
2. 每个问题开一个不带上下文的子代理，只给它文档全文和问题，看它答得对不对。
3. 再让一个子代理找歧义、隐含前提、自相矛盾。
4. 有问题就回到对应章节修改，直到读者测试不再暴露新缺口。

## 6. 各类型要点

- **学术论文**：先读 `references/library/academic/principles/academic-writing.md`（30 条原则：结论先行、术语一致、图表必须在正文解读、引用在首次出现时补全）。需要分工审稿时参考 `library/academic/agents/` 下的角色：logic-reviewer、technical-reviewer、consistency-checker、bibliography-auditor、prose-polisher。
- **营销与商业文案**：读 `library/marketing/copywriting/GUIDE.md`（价值主张、标题公式、页面分段）和 `marketing-psychology/`；邮件看 `emails/`、`cold-email/`；发布计划看 `launch/`、`content-strategy/`。
- **社交媒体图文**：读 `library/social-media/post-writer/GUIDE.md` 和 `hook-generator/`；要沉淀个人语气时用 `voice-builder/` 产出 `voice.md`。
- **研究型长文**：先走 `skills/research-and-factcheck/GUIDE.md` 建 `research.md`，再写正文。

## 7. 交付

默认 Markdown。用户要 Word 时，用 docx skill 从 Markdown 生成，标题层级、表格、脚注要保持。完成后提醒用户自己通读一遍、核对关键数字和链接。
